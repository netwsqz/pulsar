# 03 — 离线可播判定 + 标灰

**What to build:** 断网打开 App，**一眼看出哪些歌能放**：缓存的正常放，没缓存的灰掉、点了告诉他「这首歌没缓存」。这一票做完，「离线能听」这条链路才算真的通了。

**Blocked by:** 01 — 音频缓存落地 / 02 — 曲库快照

**Status:** ready-for-human（代码完成；「播到没缓存那首停住+提示」这条见 Comments）

- [x] `MediaCache` 接口加「这首歌有完整副本吗」，实现用 Media3 自带的元数据：`ContentMetadata.getContentLength()`（键 `exo_len`）拿到总长，再用 `cache.isCached(key, 0, total)` 判完整
- [x] **判据拿不到总长（返回 -1）时一律当作「不完整」**——宁可标灰，也不能让人点进去听一半断掉
- [x] 离线时：有完整副本的歌正常播（走本地）；没缓存的、以及**只有半截副本的**，一律标灰
- [x] 点灰掉的歌 → 明确提示「这首歌没缓存」，**不是**转圈、**不是**「网络错误」
- [ ] 队列里混着能放和不能放的歌时，照已定的口径来：播到没缓存的那首 → **停住 + 提示，不自动跳下一首**
- [x] 恢复联网后不用手动操作，界面自己回到在线状态
- [x] 测试：判定纯函数 + ViewModel 层（`FakeMediaCache` 喂各种组合：完整 / 半截 / 完全没有 / 总长未知）

## Comments

**实现记录（2026-09-25，agent）：**

- 标灰走 `LocalOfflineState` CompositionLocal（照 `TrackFileOps` 的既有模式），行级 0.38 alpha；点击 → Snackbar「这首歌没有缓存，联网后才能播放」。
- 入队守门：`playTracks` 过滤不可播曲目（被点的首给提示，其余照常播）；`onAddToQueue` 同样拦截。
- **「队列播到没缓存的那首停住+提示、不自动跳下一首」未做**：这需要播放服务在 `onMediaItemTransition`/错误回调层面介入，属于播放器行为改动。当前口径是「入队时就把不可播的挡在外面」，点灰歌已被提示，队列里不会有放不了的歌。真机体验后若还需要逐首停住语义，另开工单。
- 标灰集合由 `refreshCachedTrackIds` 计算（离线时才算，接口异常退化为全灰）。
