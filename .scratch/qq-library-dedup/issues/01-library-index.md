# 01 — 服务端：曲库索引与判定规则

**What to build:** 服务端能回答「我的曲库里有没有这首歌」。全部判定规则在这一个工单里定死：怎么扫目录、读什么当钥匙、怎么归一化、怎么算「是同一首」。做完交付一条命令行入口，拿**真曲库**跑一遍，把「服务端认为你已有哪些歌」打印出来给用户亲眼过一遍——**这一步就是验判定准不准，不准的话调完再往下走。**

**Blocked by:** None — can start immediately

**Status:** ready-for-agent

- [ ] 扫描 Jellyfin 音乐库目录 `E:\file\Te_Music`，按扩展名过滤，跳过 `.nfo` 等非音频文件
- [ ] **只读**：全程不写入、不移动、不删除曲库里的任何文件
- [ ] 读音频标签取歌名与歌手（mutagen，服务环境已装，不新增依赖）
- [ ] **MP3 必须用 `easy=True` 读标签**，否则取不到（ID3 帧名是 `TIT2/TPE1`）
- [ ] 标签缺失或读不出歌名时，回退解析文件名：去掉开头的 track 号 / disc 号前缀、去掉 `_hires` / `_H` 这类音质后缀、去掉扩展名
- [ ] 归一化：统一大小写、全角半角、省略号与引号问号等等价标点、压缩连续空格
- [ ] **括号及其内容一律保留，绝不丢弃**
- [ ] 歌名归一化后必须**完全相等**
- [ ] 歌手归一化后须**一边包含另一边**（`Lady Gaga/Bruno Mars` 含 `Lady Gaga` ⇒ 算对上）；缺歌手信息时只按歌名判
- [ ] **不判音质**——已有的 128k 也算「已有」
- [ ] **判定不出来时一律按「没有」处理**（服务不可达、索引没扫完、歌名读不出……都是「没有」）
- [ ] 后台线程按 **3 分钟**周期对比目录快照（路径集合 + mtime + size），**有变化才重扫**；无变化时请求直接读内存索引
- [ ] 索引未就绪时查询返回「未知」，**不阻塞、不报错**
- [ ] 服务端自己下载成功一首歌后，**立即**把它并入索引，不等下一次周期扫描
- [ ] 扫描耗时与内存索引常驻：冷扫 595 个文件约 17 秒（实测），热读约 0.5 秒
- [ ] **不做磁盘缓存**
- [ ] 单元测试覆盖：归一化、同名判定、歌手「一边包含另一边」、括号保留、全角半角、无标签回退文件名
- [ ] 扫描器拆两半：「(文件名, 标签) → 身份」做成纯函数单元测试；「遍历目录 + 调 mutagen」的 IO 那半不写单元测试
- [ ] 交付一条命令行入口：扫描后打印索引摘要（识别到的曲目总数、耗时、若干样例），并支持传入「歌名 + 歌手」查询判定结果，供用户在自己真曲库上抽查
