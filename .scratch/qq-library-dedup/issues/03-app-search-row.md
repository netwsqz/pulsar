# 03 — App：搜索结果页看得见 + 能强制下载

**What to build:** 手机上搜歌时，曲库里已经有的那些一眼能看出来（置灰 + 「已在库」标签），点它不会被默默重复下载，但确认后仍能强行下。同时在跑的任务显示成「下载中」。服务卡片上多一行曲库信息。**这是整条链路第一次在手机上跑通。**

**Blocked by:** 02 — 服务端：接口带标记 + 默认跳过

**Status:** ready-for-human

- [x] 歌曲 DTO 新增 `in_library` / `downloading` 字段，**都带默认值**
- [x] 专辑曲目 DTO 同样新增这两个字段
- [x] 状态层维护一个全局「已在库」集合，**以 song_mid 为键**；不把标记塞进服务端 DTO（那是 data 层对象，且搜索结果整批替换，挂在单曲对象上的标记每搜一次就丢）
- [x] 「下载中」集合 = 服务端回传的 `downloading` 标记 **∪** 本地任务队列里 `queued`/`running` 的 song_mid（并集：服务端保证重启 App 后仍准，本地队列保证刚点下去还没轮询到时也立刻准）
- [x] 任务轮询看到某个 mid 变为完成态时，**立刻**并入本地「已在库」集合（零额外请求、零延迟）
- [x] **搜索结果行**：已在库 ⇒ 下载图标禁用 + 一个「已在库」小灰标签，**歌名与歌手保持正常颜色**（中文歌名本来就难认，整行调暗会让人找不着歌）
- [x] **搜索结果行**：下载中 ⇒ 标「下载中」，不可点
- [x] **点已禁用的下载图标** ⇒ 弹确认「该曲已在库，仍要重新下载？」，确认则带 `force` 重发
- [x] **下载请求体带上 `artist`**（`QQDownloadRequest` 新增字段）。服务端判定「已在库」必须同时有歌名和歌手，缺歌手时它一律不拦（见工单 02 的 Comments 第 2 条）——不补这个字段，服务端那层挡重复等于没接上
- [x] 服务端回「已跳过」时不报错、不弹错误提示（它 = 已在库，界面上那首本来就该是灰的）
- [x] **健康卡片**新增一行「曲库：<目录> · N 首」；索引未就绪时显示「扫描中…」（这一行的价值在排查——它说某首歌没有、但用户明明有，用户能一眼分辨是「它看错目录了」还是「真的没有」）
- [x] **服务不可达 / 索引未就绪时，所有歌一律按可点处理**（判定不出来一律当「没有」）
- [x] 搜索速度不变：标记随搜索响应一起回来，不额外发请求
- [x] ViewModel 单元测试（扩展现有手写 Fake）：已在库集合的维护、任务完成后立刻标记、下载中并集推导、force 重发的确认流程、服务不可达时全部按可点
- [x] 数据层单元测试（Ktor MockEngine）：新字段解析；服务端返回缺这两个字段时仍能解析（向后兼容）
- [ ] 界面由用户在自己手机上**亲眼看**验证（本项目无 Compose UI 测试基建、无 `androidTest` 目录，一贯如此）

## Comments

### 实现要点（2026-09-17）

1. **两个集合两种维护方式**（这是本工单最容易做错的决策）：
   - `inLibraryMids`（已在库）**并集、只增不减**——搜索/弹窗响应、任务 done、服务端 `skipped` 都往里并。会话内一首歌不会「从库里消失」。
   - `downloadingMids`（服务端下载中标记）**每次响应整体替换**，渲染统一走计算属性 `activeDownloadingMids = downloadingMids ∪ 本地 jobs 里 queued/running`。若也做成只增不减，「下载中」标签在任务完成后永远不消失；jobs 列表是服务端队列的完整快照，替换即真源，下完自动消失。
2. **索引扫描中的重查**：`checkHealth` 首查发现 `library.ready=false` 后每 3 秒重查，直到就绪/失败/换服务地址（generation 防串）。重查轮**只刷曲库字段**，不碰 errorMessage——别让后台轮询冲掉界面上的其他报错。老服务端没有 `library` 块时 DTO 默认 `ready=true`，不误报扫描中。
3. **灰图标仍可点**：Material 3 的禁用 IconButton 收不到点击，所以「已在库」的下载图标用 38% alpha 置灰但保持可点，点了弹重下确认——「看着禁用、点了问你」正是工单要的交互。
4. **「已跳过」静默处理**：`skipped=true` → mid 并入已在库集合（行立刻变灰），不报错、不弹提示、不启动轮询。
5. **曲库信息行**放在音质 chips 下方，连接后常显；老服务端（无索引）`libraryRoot` 为空则隐藏该行。

### 测试

- ViewModel（手写 Fake）新增 13 个：标记并入、服务不可达全可点、`artist` 透传、skipped 静默、重下确认/取消、轮询 done 立刻并入且「下载中」消失、扫描中→就绪、全选未下载、下载中不可勾、显式勾选照发、汇总文案、整张跳过回报（部分/全部两种）。
- 全仓 `:app:testDebugUnitTest` 435 个全绿；`:app:assembleDebug` 构建通过。

### 待用户真机验证

- 搜一首库里有的歌：行带灰色「已在库」标签、下载图标灰；点它弹确认，确认后能重下。
- 正在下载的歌：标「下载中」且不可点；下完自动变「已在库」，不用重搜。
- 健康行：连接后显示「曲库：E:\file\Te_Music · N 首」；服务刚启动时显示「扫描中…」并自动转为就绪。
