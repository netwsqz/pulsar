**Blocked by:** 03 — App：搜索结果页看得见 + 能强制下载

**Status:** ready-for-human

- [x] 弹窗顶部一行汇总：**「共 12 首 · 已有 8 首」**
- [x] 弹窗曲目行：已在库 ⇒ 带「已在库」标签，**能勾但默认不勾**；勾上就照下，不再弹确认（勾选本身就是明确意图，不用再问一遍）

## Comments

### 实现要点（2026-09-17）

1. **弹窗读全局集合，不读 DTO 字段**：曲目行/汇总行从 `state.inLibraryMids` 与 `state.activeDownloadingMids`（工单 03 的计算属性）取标记，弹窗开着时轮询更新也能实时反映（比如别的任务下完，对应行的「下载中」自动消失）。
2. **汇总文案是顶层纯函数** `albumPickerSummary(tracks, inLibraryMids)`（`QQDownloadViewModel.kt`），直接单元测试，不依赖 Compose。
3. **「全选未下载」用并集而不是替换**：`selectedMids + 未下载的`——用户手动勾上的已在库曲目不会被全选按钮冲掉。
4. **整张跳过的提示走 `errorMessage` 通道**（沿用「有 N 首已不在该专辑内」的先例）：部分跳过 →「已跳过 N 首（已在库），新加入下载 M 首」；整张全有 →「整张 N 首都已在曲库，未重复下载」。
5. **确认下载仍显式带 `song_mids`**（原行为不变）：服务端对显式选曲不跳过——弹窗里手动勾上的已在库曲目就是靠这条「勾了照下」。

### 测试

- 全仓 `:app:testDebugUnitTest` 435 个全绿；`:app:assembleDebug` 构建通过。
