# 07 — 歌曲与搜索列表行（含共用空态/文案）

**What to build:** 歌曲页和搜索页的列表行用同一套语法：前槽、间距、文字列、尾槽一致；多选时分隔线从文字左缘开始；骨架和真实行同高，加载完不跳；空态居中；行尾按钮和勾选框都有足够热区。歌曲页标题直接叫「歌曲」，离线提示的字号不低于行内副标题。

**Blocked by:** 01（设计 token 收口与设置页底部留白）。

**Status:** ready-for-human（代码完成）

**规格参考：** `spec.md` §5、§11

- [x] 标题一行 bodyLarge，副标题一行 bodySmall 次要色；当前曲目标题用 primary。

## Comments

### 实现记录（2026-11-01，agent）

**改了什么**

- **新增共享行布局** `ui/components/MediaList.kt`：`MediaRowLayout`（前槽 48 / 间距 12 / 文字列
  `weight(1f)` / 尾槽 48 可空 / 上下 8 / 最小行高 64）+ `MediaRowText`（标题 `bodyLarge` 一行、
  副标题 `bodySmall` 次要色一行）。分隔线起点 = 传入的实际前槽宽 + 12，不再写死 60dp。
- **`TrackRow` 迁到共享布局**：多选时前槽 = 勾选框 48 + 4 + 封面 48 = 100，分隔线从 112dp
  （文字左缘）开始；无多选 / 专辑详情序号槽 = 48，分隔线从 60dp（封面右缘）开始。勾选框显式
  `size(48dp)`，行尾「更多」仍是 48dp `IconButton`。手势（combinedClickable / 长按锚点测量）
  原样挂在行上，行为不变。
- **`SearchResultRow` 迁到共享布局**：搜索结果里的专辑 / 播放列表行、艺术家列表行现在与歌曲行
  共用同一套槽位、字号、分隔线基准。
- **骨架与真实行同构**：`TrackListSkeleton` 改用 `MediaRowLayout`（48/12/48 + 8dp 内边距 +
  同款分隔线），`trailingSpace` 用空的 48dp 尾槽占位——加载完成文字列与行宽不跳。
- **空态 / 错误态**：`EmptyState` / `ErrorState` 内部统一 `fillMaxWidth()` + 文案 `TextAlign.Center`，
  调用方不用再各自补；图标与文案在整行宽度内居中。
- **文案**：歌曲页标题从 `TopLevelSections` 取（显示「歌曲」），不再写「你的音乐」；
  `OfflineNoticeText` 从 `labelSmall` 升到 `bodySmall`，与行内歌手副标题同号。
- **Dimens**：新增 `MediaRowMinHeight = 64.dp`（行高是跨页面布局规格，不是单个组件内部尺寸）。

- `:app:testDebugUnitTest`：**664 个用例，0 失败**。

**代码审查后修正**

- Spec：`EmptyState` / `ErrorState` 的图标尺寸从字面量 `48.dp` 改为 `Dimens.TouchTargetSmall`
  （spec §5 要求空态/错误态的间距与图标尺寸走 Dimens）。
- Standards：删掉专辑详情两处与组件内部新默认值重复的 `Modifier.fillMaxWidth()`；
  搜索页一处全限定 `TextAlign.Center` 改为已 import 的短名。
- Standards 提出但未改：①前槽宽度公式与槽内组件尺寸仍是两处书写（布局规格本身就是
  「勾选框 48 + 4 + 封面 48」，注释已标明对应关系；改成实测宽度会有一帧分隔线错位）；

  ③`DownloadedAlbumRow` 等其它手写行不属本单（歌曲/搜索/播放列表/艺术家行）范围。
