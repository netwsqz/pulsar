# 规格：前端显示收敛（曲库主流程）

**Status:** ready-for-agent

> 输入：`.scratch/ui-display-audit/report.md`（原始 75 条，去重后 69 条；高置信 7 条，待真机确认 62 条）。本规格只收敛方向与边界；报告里标「待真机确认」的条目在动手前仍要代码复核或真机复现，不能把静态推断当已确认 bug 直接修。
>
> 视觉语言不变：液态玻璃、M3 色板、封面取色都保留。这次是「外壳收敛 + 根因修复」，不是换一套设计。

## 问题陈述

从使用者角度看，现在的曲库主流程有六类疼：

1. **深色主题下外壳看不清。** 迷你播放条的歌名、玻璃岛的页签和图标、展开面板里的时间、音量胶囊上的数字，在深色玻璃上仍是默认黑色。浅色下恰好能看，所以一直没暴露。
2. **浮层各摆各的。** Snackbar 固定距底 80dp，会压住 64dp 高的迷你条；多选条和音量胶囊抢同一个顶部位置；底部内容留白在每个页面各写一遍 96dp；玻璃岛、迷你条、Snackbar 的外边距各写 12/8dp。
3. **列表没有统一行语法。** 歌曲行、搜索结果行、播放列表行、艺术家行各写一套；多选时分隔线不跟勾选框走；骨架和真实行不同高，加载完内容往上跳；空态贴左；专辑卡副标题和标题同色、不限行、卡高参差。
4. **详情页没有统一骨架。** 播放列表详情加载时把头部画了两遍；长标题没有上限会把曲目列表挤没；曲目数和实际行数不同源；没有播放全部/随机播放；离线摘要把「已下载」的数量当成总数。
5. **离线时发现页的三节服务器历史没有隐藏。** 最近播放/最常播放/最近添加直接用原始数据（`goOffline()` 不清它们），离线时仍显示没下载的内容，点进去是空详情；`hasAnySection` 也会因此压制整页空态。按 ADR-0008 决定 5，离线时这三节应当整个不显示。
6. **下载和动效缺少「未知/停止」态。** 已下载的专辑打开时先闪一个可点的「下载」；部分失败的重试绕过蜂窝确认；删除下载没有进度；播放指示器和「换一批」在不需要时仍一直动画。

另外，**流派页**是顶层导航里几乎不用的一个维度，与艺术家页共用同一套列表/详情实现，维护成本高于价值，已决定彻底删除。

这些问题的共同点是：它们不是 69 个互不相关的 bug，而是 6 条根因的重复表现。逐条打补丁会把同一个问题修很多遍，所以先修根因。

## 解决方案

一次「外壳收敛」：

- **玻璃面统一前景色**：所有玻璃面共用一个内容色来源，深色下文字/图标自动变成 onSurface，不再每个控件单独调颜色。
- **浮层统一锚点**：顶部只放导航/选择，底部只放瞬时反馈；Snackbar 和音量胶囊锚定在实测播放条高度之上，多选条固定在玻璃岛下方；所有外边距、圆角、底部留白从同一套 token 来。
- **外壳做减法**：玻璃岛变成「搜索 + 可横滑页签 + 更多」三段；设置和退出登录收进「更多」；已下载列表仍从设置页「下载」卡片进入（ADR-0007），QQ 音乐导入仍是设置二级页（ADR-0006）。迷你条只留封面、歌名、播放、展开。不新增底部导航。
- **列表一套行语法**：所有列表行共用同一个「前槽 48 / 间距 12 / 文字列 / 尾槽 48」布局，骨架与真实行同构，分隔线跟着前槽走，空态统一居中。
- **详情一套页面骨架**：真实头部永远只画一次，后面是操作行、下载槽、离线提示、曲目状态；专辑、播放列表、艺术家组共用同一套骨架的不同变体。
- **离线可见性补全**：发现页三节服务器历史在离线时整个隐藏（ADR-0008 决定 5）；详情计数按实际可见曲目；离线未下载的播放列表给说明型空态，不再给必然失败的重试按钮。
- **下载补状态机**：字节校验完成前显示禁用的「检查中…」；所有入队入口统一走蜂窝确认；删除有进度和结果反馈。
- **删除流派页**：顶层从 6 项变 5 项，艺术家路径原样保留，`Album.genres` 数据字段保留。

## 实现决策

### 1. 玻璃面：统一提供前景色

- 新增 `GlassPanel` 薄包装：先提供 `LocalContentColor = MaterialTheme.colorScheme.onSurface`，再套用现有的液态玻璃修饰符。
- 这是所有玻璃内容的唯一入口：顶部玻璃岛、迷你播放条、展开面板、队列面板、音量胶囊、多选条、长按菜单。
- 不在任何 `Icon` / `Text` 上单独写 tint。逐个补色会把同一个问题修很多遍，而且以后新增玻璃控件还会漏。
- 选中的页签 chip 保持 `onPrimary`（现有 FilterChip 颜色是显式设置的，不受影响）；实施后深浅两色都要确认。

### 2. 浮层几何：一个底部锚点栈

- 底部 overlay 栈：Snackbar 与音量胶囊共用 `navigationBarsPadding() + 实测播放条高度 + FloatingVerticalMargin`。
- 迷你播放条通过 `onGloballyPositioned` 上报自身高度（展开面板属于它的一部分，高度自然包含面板）；首帧用 `PlayerDockHeight` 兜底。不为消除一帧误差引入 `SubcomposeLayout`。
- 顶部槽位只放导航与选择：多选操作条固定在玻璃岛下方（`GlassIslandTopSpacing + FloatingVerticalMargin`），高度 56、圆角 20、左右 `FloatingHorizontalMargin`，改用玻璃材质。
- 音量胶囊从顶部移到底部 overlay 栈；多选时两者都可见。
- 下拉刷新的转圈要落在状态栏和玻璃岛下方；用顶部内边距或自定义 indicator，保证第一帧就可见。

### 3. 外壳结构：玻璃岛三段式

- 左：搜索 48dp；中：可横滑页签 `weight(1f)`；右：更多 48dp。
- 页签顺序与文案仍由 `TopLevelSections` 唯一决定；`navIndex()` 按列表位置推导，不写硬编码索引。
- 「更多」菜单只收：设置、退出登录。已下载列表仍从设置页「下载」卡片进入（ADR-0007），QQ 音乐导入仍是设置二级页（ADR-0006），不另开全局入口。退出登录必须二次确认。
- 不新增底部导航：底部已被播放条占用；再加 56dp 会把内容区压到 500dp 以下。

### 4. 迷你播放条

- 折叠态只保留：封面 40、歌名/歌手 `weight(1f)`、播放/暂停 48、展开 48；上一首/下一首从折叠条移除（全屏页与横滑手势仍在）。
- 360dp 屏上文字列目标 ≥ 160dp（按报告核算为 164dp）。
- 播放/暂停只在 `controller != null` 且有媒体项时可用；队列为空时禁用。
- 队列面板：分区标题与歌名拉开字号/字重层级；标题行最小高度 48dp；移除按钮 48dp 热区、图标保持 16dp。
- 空态封面复用 `AlbumCover` 的空占位，自动获得圆角，不再是直角灰块。
- 移除上一首/下一首是产品取舍，单独提交、真机试用后再决定是否恢复；可先只保留「下一首」一个按钮（歌名回到约 116dp）。

### 5. 列表：一套行语法

- 新增 `MediaRowLayout`：前槽 48（封面 / 序号 / 勾选框+封面）、间距 12、文字列 `weight(1f)`、尾槽 48（可空）、上下 8、最小行高 64。
- 标题 `bodyLarge` 一行；副标题 `bodySmall` 次要色一行；当前曲目标题用 primary。
- 分隔线起点 = 当前实际前槽宽度 + 12dp（无多选 60dp，多选 112dp，序号 60dp），不再写死。
- `TrackRow`、`SearchResultRow`、播放列表行、艺术家行全部迁到它。
- 骨架与真实行同构：曲目骨架用同样的 48/12/48 槽位与 8dp 内边距；专辑详情用序号槽而非假封面；组详情网格骨架带两行标题 + 一行副标题的文字区，并 `fillMaxSize()` 从顶部开始。
- 空态：所有调用点传 `fillMaxWidth()`，图标与文案居中；错误态/空态的间距与图标尺寸走 Dimens。
- 专辑网格：标题 `minLines=2, maxLines=2` 固定两行；副标题 `onSurfaceVariant`、`maxLines=1`；卡片高度稳定，骨架同高。

### 6. 详情：一套页面骨架

- 新增 `MediaDetailScaffold`：整页一个 LazyColumn，顺序固定为「真实头部（永远不骨架）→ 操作行 → 下载槽 → 离线提示 → 曲目状态（骨架/错误/空/真实行）」。
- 头部规格：封面 `fillMaxWidth(0.62f)` + 1:1 + `CornerLarge`；标题 `headlineSmall` 粗体、居中、最多两行；副标题 `bodyLarge` 次要色一行；摘要 `bodySmall` 次要色。
- 专辑与播放列表共用同一骨架；艺术家组用网格变体。
- 操作行：播放全部 + 随机播放，按钮高 40、间距 12；下载按钮在操作行下方 12；离线隐藏下载。
- 播放列表不再用左侧 120dp 小封面 + 左对齐文字，改成与专辑同一语言。
- 播放列表的播放/随机/计数基于当前实际可见曲目：曲目已加载用列表长度，未加载才退回 `trackCount`；离线摘要写「已下载 N 首 · 共 M 首」。
- 播放列表标题 `maxLines=2`，文本列 `weight(1f)`。
- 副标题统一次要色，不和标题同强调级。

### 7. 离线：补全可见性规则

- **三节服务器历史离线时整个隐藏**（ADR-0008 决定 5）：最近播放 / 最常播放 / 最近添加在离线时不组合、不给骨架、不给空态；它们的数据保留在 state 里，回在线再显示。
- `hasAnySection` 只统计实际会渲染的节：离线时只看每日推荐与随机专辑墙，在线时再加上三节历史。
- **不扩展 `VisibleLibrary`**：三节历史不是「过滤后展示」，而是「离线不展示」，用 `isOffline` 做组合条件即可，避免给派生数据类加字段。
- 其余离线规则沿用现有 `offlineVisibleLibrary`：曲目按已下载 id；专辑「有一首已下载就保留」；详情只列已下载并隐藏下载按钮。
- 详情摘要按实际可见曲目计数，并显示离线提示；播放列表的计数与播放/随机同样基于可见曲目。
- 离线且未下载的播放列表：渲染说明型空态，不渲染重试按钮。
- 原始 `JellyfinUiState` 一律不动；回在线自动恢复全量。

### 8. 下载：补「未知态」与单一入队漏斗

- 字节校验结果从 `Boolean` 改成 `Boolean?`：`null` = 检查中。调度器没有进行中状态时，按钮显示禁用的「检查中…」，不再先闪可点的「下载」；下载中/部分失败仍然优先。
- 表示法：`resolveDownloadState(live, allTracksComplete: Boolean?): DownloadState?`，返回 `null` = 检查中；**不往调度器的 `DownloadState` sealed 类型里加 `Checking`**，调度器核心不动。target 为空/空专辑时调用方传 `false`，收口为未下载，不能永远停在检查中。
- `resolveDownloadState` 是按钮状态的唯一出口，覆盖「调度器状态 × 字节真相（null/true/false）」矩阵。
- 所有入队入口（下载、失败重试、继续下载）统一走 `requestDownload()`；蜂窝确认只在一处判断。
- 部分失败改用 `FilledTonalButton` + 刷新图标（errorContainer），强调级与其它三态一致。
- 删除确认后显示进度；完成后关闭对话框并回调 Snackbar「已删除 N 首」。

### 9. 动效

- 播放指示器：只在 `isPlaying` 时创建无限动画；用 draw 阶段（`drawBehind` 或 `graphicsLayer scaleY`）绘制，不逐帧改布局高度；暂停时静态。
- 暂停态遮罩提高到 0.45–0.5，指示条改白色/onPrimary，保证压在封面上可辨。
- 「换一批」：用 `Animatable` 只在加载时循环；停止时补到最近的 360° 整倍数再停，不回正。
- 封面底部渐变按封面高度比例（约 25%）并设 32dp 上限，40dp 小封面不再被压暗大半。
- 无刷新、无播放时不应有持续动画帧。

### 10. 长按菜单与对话框

- 长按菜单从 `Popup` 提升到主窗口 overlay（`Popup` 是独立窗口，采样不到主窗口 backdrop，这是当初手写玻璃的技术原因），使用同一个 `GlassPanel`。
- 菜单宽 240、行高 48、圆角 `CornerLarge`；阴影安全区与内容内边距共用一个 `MenuEdgePadding`（= SpaceMedium），不再两处 16dp 人工同步。
- 删除项与删除确认用 error 色；改名等普通项用默认/主色。
- overlay 要手动补齐 `Popup` 原本提供的行为：焦点、返回键、点外关闭、z 序；先在一个页面验证再全量替换。
- 改名弹窗：输入区可滚动并处理 IME，按钮区固定在滚动区外。

### 11. 文案与信息层级

## 测试决策

本功能不引入 Compose UI 测试设施，继续沿用项目现有的纯函数缝。缝越少越好，最高缝就是「离线可见性 + 下载状态 + 导航/分组」这三处纯函数。

**要测的缝：**

1. **`offlineVisibleLibrary`（最高缝）**——维持现有用例：曲目按 id 过滤、专辑「有一首已下载就保留」、`null` 保持 `null`、空集合与 `null` 的区分。三节历史的离线隐藏是 UI 组合条件，没有纯函数缝，靠真机离线验收。
2. **`resolveDownloadState`**——签名定为 `resolveDownloadState(live, allTracksComplete: Boolean?): DownloadState?`，返回 `null` 表示「检查中」；`Downloading` / `PartiallyFailed` 优先；target 为空时调用方传 `false`，不得停在检查中。测试覆盖「调度器状态 × null/true/false」矩阵，至少包含：检查中不显示已下载/未下载、下载中 × 检查中仍显示下载中、target 为空收口为未下载。沿用现有 `DownloadActionButtonTest`（旧用例因 `Boolean` 可赋给 `Boolean?` 仍可编译）。
3. **`libraryGroups`**——流派删除后只按艺术家分组；沿用 `LibraryGroupsTest` 现有边界用例（大小写不敏感、空白/UNKNOWN_ARTIST 不建组、稳定排序）。
4. **`TopLevelSections` / `navIndex` / `navLabel`**——断言按类型而不是硬编码索引；沿用 `LibrarySectionTest`。
5. **`Album.genres`**——数据层保持现状，现有 DTO / DataSource 测试不动。

**测什么：** 只测外部行为——喂数据进纯函数，断言返回的列表/状态。不断言内部调用顺序，不测 Composable 树。

**不测什么：** 玻璃材质、间距、字号、颜色、动画、手势、Snackbar 位置。仓库没有 Compose UI 测试设施，这些靠真机肉眼验收。

**先 RED：** 每个行为改动先写失败用例（项目 TDD 强约定），再改实现；下载状态与分组/导航改动尤其要先补用例，离线列表过滤沿用现有用例。测试命名沿用反引号中文行为描述。

**构建：** `:app:testDebugUnitTest` 与 `:app:assembleDebug` 必须通过。

**真机验收：** 深/浅色 × 360dp ×（手势导航、三键导航）；离线覆盖发现页三节历史、专辑详情、播放列表详情、搜索；下载覆盖已下载专辑不闪「下载」、Wi-Fi 下载→切蜂窝→失败重试弹确认、删除有进度；动效覆盖静止时无持续动画、暂停后指示器静止。完整清单见报告 8.3。

## 明确不做

- 设置页、搜索页、QQ 音乐导入页的其余问题（第二批，报告第 6 节）。例外只有设置页底部留白（P1）。
- 流派页的 `Album.genres` 数据字段、DTO、`Fields=Genres` 请求参数：保留。
- 全屏播放页（`NowPlayingScreen`）的视觉排查与修改。
- 登录页完整排查（只顺手把间距换成 token）。
- 字体缩放、横屏、平板/大屏适配：本轮不覆盖，仍是已知盲区。
- 底部导航：不做。
- 换视觉语言：液态玻璃、M3 色板、封面取色、字体与图标体系都不换。
- 新增依赖、新增 Compose UI 测试设施：不做。
- 播放服务、USB 独占、回放增益、静音跳曲、下载调度器的核心逻辑：不动；下载只改按钮状态与入队漏斗。
- 多选功能的交互模型：保留现状（只统一材质与间距）。
- 搜索框本身的交互（300ms 防抖等）：不动。
- 专辑网格列数、详情页封面「色晕」等大改版：本轮不做，报告只把它们列为可选方向。

**风险：**

- `GlassPanel` 会改变浅色主题图标颜色（黑 → onSurface 近黑），这是预期；要检查选中 chip 的 `onPrimary` 标签没有被覆盖。
- 实测 dock 高度有一帧延迟，首帧 Snackbar 用 `PlayerDockHeight` 兜底；不要为这一帧引入复杂布局。
- 移除上一首/下一首是产品取舍，不是技术必需；单独提交，真机试听后再决定是否恢复。
- 音量浮窗移到底部会改变 USB 独占用户的操作记忆；但当前多选时它根本不可见，底部是净收益。
- 长按菜单从 `Popup` 迁到同窗 overlay 涉及焦点、返回键、点外关闭、z 序，风险最高；先做一个页面验证。
- `MediaDetailScaffold` 是最大改动：先单独修播放列表的重复头部/maxLines/计数/缺播放按钮，再抽共享骨架，不要一次重写专辑、播放列表、组详情三页。
- 三节历史的离线隐藏是 UI 组合条件，没有单测兜底；实现时把 `hasAnySection` 与实际渲染条件放在同一处，避免两处判断漂移。
- 96dp 清扫机械但容易漏，验收时 grep。
- 流派删除可能碰硬编码导航索引；`navIndex()` 改为按列表位置推导，并让 `LibrarySectionTest` 兜底。
