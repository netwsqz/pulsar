## 一句话结论

一个搜索页、一个输入框，一次输入同时问曲库和 QQ 音乐；QQ 下载退出顶层导航，降级为「设置 → 下载」二级页。

## 新窗口需要知道的三件事

1. **别新建聚合 ViewModel。** 两个 ViewModel 各跑各的 300ms 防抖，UI 层同时调两边的 `updateSearchQuery` 即可。
2. **QQ 侧失败只降级。** 电脑没开 / 凭证过期时，曲库搜到的结果必须照常显示；QQ 的失败只能落在分区内的小字里，不能走整页错误。
3. **错误字段要拆。** 搜索期失败（常驻小字）与下载动作反馈（Snackbar）现在共用 `QQDownloadUiState.errorMessage`，这是本次唯一有回归风险的地方。`handleApiError()` 有 8+ 个写入路径，逐个归类，不确定的归 Snackbar。

## 设计决定速查

| # | 问题 | 结论 |
|---|---|---|
| 1 | 合并形态 | 单页单框，结果分区混排（不做来源 chip / tab） |
| 2 | 请求策略 | 每次搜索双打；QQ 失败只降级 |
| 3 | QQ 结果内容 | 单曲 + 专辑都保留 |
| 4 | QQ 顶层 chip | 去掉，降为设置二级页 |
| 5 | 已在库的歌 | 照旧显示并标记，点击弹重下确认 |
| 6 | 不可用表达 | 分区内小字 + 重试，不染红 |
| 7 | 防抖 | UI 层分发，两边各自防抖 |
| 8 | 任务列表 | 进设置 → 下载页 |
| 9 | 设置页位置 | 「播放」与「存储」之间，叫「下载服务」 |
| 10 | QQ 分区排布 | 总标题「QQ 音乐」+ 子小节「歌曲 / 专辑」 |
| 11 | 搜索页音质 chip | 不放 |
| 12 | 重试入口 | 小字后跟「重试」文字按钮 |
| 13 | 弹窗挂载 | 挂在搜索页，不做全局弹窗 |
| 14 | 设置页形态 | 二级页（`QQDownloadScreen` 去掉搜索区原样复用） |
| 15 | 下载后刷新 | 不自动刷新 |
| 16 | QQ 分区位置 | 永远在曲库之后 |
| 17 | 曲库空 QQ 有结果 | 上方加「曲库中没找到「X」」 |
| 18 | 离线提示 | 改为「曲库离线 · 只搜手机上的快照；QQ 音乐不受影响」 |
| 19 | 下载动作反馈 | Snackbar（复用现有 `SnackbarHost`） |
