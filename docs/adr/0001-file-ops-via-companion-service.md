# ADR-0001：文件管理走 PC 伴生服务，不走 Jellyfin API

**状态：** 已接受（2026-09-18）

## 背景

App 要支持删除和改名曲库里的音乐文件。文件在电脑上（`E:\file\Te_Music`），Jellyfin 只是它的索引。所以「谁去动文件」有三条路：

1. Jellyfin 自带 API
2. PC 伴生服务（`server/qqmusic_service.py`）扩一组接口
3. 手机直连电脑的文件共享（SMB）

## 决定

**走 PC 伴生服务。** Jellyfin API 一个都不用。

## 理由

Jellyfin 在**两个关键能力上都做不到我们要的语义**：

| 我们要的 | Jellyfin API | PC 服务 |
|---|---|---|
| 删除 = 移到回收站（可恢复） | ❌ 只能真删 | ✅ 挪文件 |
| 改名 = 改文件内嵌标签 | ❌ 只改数据库，**且重扫会被文件里的旧标签盖回去** | ✅ `mutagen` 直接写 |

第二条是致命的：Jellyfin 的元数据编辑是**数据库侧覆盖**，不是改文件。用户辛苦改完名字，Jellyfin 一次重扫就还原了。而且这不是 bug——Jellyfin 的定位就是「读标签、不改标签」，它自带元数据编辑器只是用来做数据库侧覆盖的（官方还提供「锁定字段」来防止被重扫覆盖，等于承认了这一点）。

SMB 那条能办到这两件事，但要在手机上处理电脑的账号密码，比扩一组 HTTP 接口麻烦得多。

## 后果

**换来的：**

- 「移到回收站」「恢复」「真改标签」都能做，且改的是**真数据**，不怕重扫
- 复用了服务已有的东西：`LIBRARY_ROOT` 常量、`_parse_final_path` 那套路径校验、`mutagen` 依赖、`library_index.read_tags` 的读标签写法

**代价：**

- **电脑上的服务必须开着**，否则 App 里删不了改不了（跟现在的下载功能是同一个约束，用户已知）
- 危险接口暴露在局域网上 → 必须配文件操作密钥（见 `CONTEXT.md`）
- 服务**没有** Jellyfin 的库状态，改完删完得靠 Jellyfin 自己的实时监控去发现。**已知风险**：如果实时监控只盯「新增文件」不盯「文件被改」，改标签后 App 重启可能显示回旧名，直到 Jellyfin 全量扫描。待实测，真有问题再调 Jellyfin 的刷新接口补。

**被否掉的方案，以后别再提：**

- 用 Jellyfin 的 `POST /Items/{id}` 改元数据 —— 只改数据库，会被重扫盖回去
- 用 Jellyfin 的 `DELETE /Items/{id}` 删除 —— 只能真删，做不出回收站
