# ADR-0004：UI 复刻 Auxio，但只取设计规格、不取代码

**状态：** 已接受（2026-10-16）

## 背景

要参考 Auxio（开源音乐播放器）重做 Pulsar 的界面：发现页、QQ 下载页，并用 Auxio 的页面形态替换一部分现有库页（全部音乐 / 专辑 / 播放列表），另加艺术家 / 流派两个维度。

直觉上「复刻 Auxio」= 去它仓库把布局文件搬过来。**但这条路走不通，而且有两个独立原因。**

## 决定

**只取 Auxio 的设计规格（尺寸 / 色值 / 圆角 / 布局思路），全部用 Compose 自己重写。不复制它的任何源码。**

## 理由

两条独立的否决理由，任何一条单独成立：

1. **架构不同，抄不了代码。** Auxio 是传统 View 架构（XML 布局 + Fragment + RecyclerView/ViewPager2 + ViewBinding），**不是 Jetpack Compose**。Pulsar 是 Compose。它的布局文件对 Pulsar 没有一行可直接使用——搬过来也是废纸。可用的只有「它想表达什么布局」这层意图，以及 XML 里那些**显式数值**（间距、圆角、触摸目标、字重）。

2. **许可 GPL-3.0，抄代码有传染性。** Auxio 是 GPL-3.0。复制其源码会让 Pulsar 也受 GPL 约束（必须开源）。而我们要的是「参考设计」不是「fork 项目」。

**设计规格的数值本身不受版权保护**——间距 4/8/12/16/20/24 dp、触摸目标 48/56/64 dp、圆角 16/20 dp、负 letterSpacing 这类常量，是行业通用量纲，拿来用没有问题。

## 后果

- 复刻是**重写**，不是搬运：每个组件都要自己写 Compose 版，工作量比「搬代码」大，但没有法律和架构债
- 可以精确对齐 Auxio 的**视觉量纲**（这套规格记在 `research-auxio.md`），保证「神似」
- **发现页没有 Auxio 参照**：Auxio 的 Home 就是曲库列表本身（顶部 tab 切 Songs/Albums/…），**没有**「最近播放 / 最常播放 / 最近添加」这类个人化聚合。所以 Pulsar 的个人化聚合发现页是**自创设计**，不是复刻——将来有人问「Auxio 哪来的这个页」，答案是没有，是我们自己设计的
- **Auxio 的「操作逻辑」本次不复刻**（长按多选、拖拽排序、tab 可配置等）。只做界面与布局结构

**被否掉的方案，以后别再提：**

- 把 Auxio 的 XML 布局文件搬进 Pulsar —— 架构不同（View vs Compose），搬了也不能用
- 复制 Auxio 的 Kotlin/XML 源码片段 —— GPL-3.0 传染
