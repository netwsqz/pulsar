# ADR-0006：搜索合并，QQ 下载退出顶层导航

**状态：** 已接受（2026-10-19）

## 背景

曲库搜索（`LibrarySection.Search`）和 QQ 音乐搜索（`LibrarySection.QQDownload`）原本是两个页面、两个搜索框。想找一首歌时，用户得先在曲库搜一遍，搜不到再切到 QQ 下载页搜一遍——同一个关键词输入两次。

两个搜索**本来就是同一个动作的两个来源**：曲库里有就直接播，曲库里没有就去 QQ 下。它们不该是两页。

## 决定

**1. 一个搜索页，一个输入框，一次输入同时打两边。**

结果排布固定为：

```
歌曲（曲库）
专辑（曲库）
播放列表（曲库）
QQ 音乐            ← 总标题，说明下面要下载
  歌曲
  专辑
```

- QQ 分区**永远排在曲库之后**：曲库是能直接播的，优先级更高。曲库为空时它自然顶上来，不做位置漂移。
- 曲库为空、QQ 有结果时，在 QQ 分区上方加一行「曲库中没找到「X」」——把「搜过了确实没有」说清楚。
- 曲库小节标题不改名（仍是「歌曲 / 专辑 / 播放列表」），来源由「QQ 音乐」总标题一次性交代。

**2. 两边各跑各的 300ms 防抖，由 UI 层同时调用两个 ViewModel。**

不新建聚合 ViewModel。两个防抖同时启动、同时到期，实际效果就是一次防抖。

**3. QQ 侧失败只降级，不打断曲库搜索。**

- 搜索页的 QQ 分区只显示一行小字 + 「重试」：连不上下载服务 / 凭证已过期。
- **绝不**把 QQ 的失败渲染成整页错误——曲库明明搜到了，不能被另一边的故障盖掉。
- 离线（Jellyfin 走快照）时**照常搜 QQ**：两个服务是独立进程，Jellyfin 连不上不代表电脑没开。此时「离线搜索」提示的文案改成「曲库离线 · 只搜手机上的快照；QQ 音乐不受影响」。

**4. QQ 下载不再是顶层页，降级为「设置 → 下载」二级页。**

顶层 chip 只剩：发现 / 歌曲 / 专辑 / 艺术家 / 流派 / 播放列表。原来 QQ 页上的家当全部搬进二级页：

- 服务状态、凭证过期横幅与重试、文件操作密钥、曲库索引信息、下载任务列表、默认音质

搜索页**不放音质 chip**：音质是一次性偏好，不是每次搜索都要改的东西。

**5. 已在库的 QQ 歌曲照旧显示并标记。**

不隐藏、不沉底。行右侧显示「已在库」，点了弹「重新下载？」确认。隐藏会让用户以为搜不到；沉底会打乱服务端的相关性排序。

**6. 下载动作的反馈走 Snackbar。**

音质不可用、入队失败、整专跳过 N 首——这些是**动作反馈**，不是搜索结果的一部分，走 App 已有的 `SnackbarHost`。分区内那行小字只负责「服务不可用」这类持续状态，两者不共用渲染路径。

**7. 下载完成后不自动刷新曲库搜索结果。**

Jellyfin 的文件监控有延迟，立刻重搜多半还是搜不到，反而制造「下完了但没出现」的困惑。QQ 行上的「已在库」标记已经说明了状态。

**8. 弹窗跟着搜索结果走。**

「重新下载？」确认框和专辑选曲弹窗挂在搜索页上，状态仍由 `QQDownloadViewModel` 持有。不做全局弹窗——目前只有搜索页能发起下载。

## 理由

- **一个动作一个入口**：用户脑子里是「我要找这首歌」，不是「我要去哪个来源找」。两个搜索框是实现的产物，不该漏到界面上。
- **顶层导航只放「曲库的浏览维度」**：发现 / 歌曲 / 专辑 / 艺术家 / 流派 / 播放列表都是曲库的切法。QQ 下载不是曲库的一个维度，是「往曲库里加东西」的工具，属于设置。
- **降级不报错**是这套系统已有的原则（发现页三节独立降级、离线快照兜底）：一个来源挂了，其余照常。

## 后果

- `LibrarySection.QQDownload` 从 `TopLevelSections` 移除，新增 `LibrarySection.DownloadService`（二级页，`isDetail() == true`），从设置页进入，返回键回设置页。
- `QQDownloadScreen.kt` 去掉搜索框与结果列表后整体作为二级页复用；`QQSongRow` / `QQAlbumRow` / 两个弹窗移到搜索页使用。
- `LibrarySectionTest` 的顶层顺序断言同步更新。
- 文案里的「去 QQ 下载页」统一改成「设置 → 下载」。

**被否掉的方案，以后别再提：**

- **来源 chip / tab（全部 / 曲库 / QQ）**：结果本来就少时是纯噪音，且用户还得点一下才知道另一边有没有，没解决「搜一次要搜两遍」。
- **曲库为空才搜 QQ**：同一关键词在两次搜索间行为不一致，用户无法预期。
- **把两边结果混进同一个「歌曲」小节**：两种行的点击行为完全不同（播放 vs 下载），混排迟早误触。
